# Critical review — `enzyme_discovery_agent`
Date: 2026-10-28 · Scope: live source tree (excludes `runs/`, `campaign_inputs/`). Reviewer: SWE + agentic-AI + computational-enzymology lenses. Method: direct read of agent loop, chemistry/mechanism layer, ranking, prompts, firewall; three parallel sub-audits (gates, tool/DB integration, tests) with key claims re-verified against source.

## A. Executive assessment

This is a mature, unusually self-aware system. Three things are genuinely strong:

1. **The data-leakage firewall holds where it matters most.** Candidates can only enter the registry via live DB lookups: `screen_candidates` (`tools/reasoning.py:454`) and `evaluate_candidate` (`:769`) both fetch the real UniProt record and hard-reject on identity/direction failure, so the LLM cannot inject a hallucinated or answer-shaped accession. The live code tree is clean of benchmark substrate/enzyme names. This is the central scientific safeguard and it is real.

2. **The mechanistic chemistry layer is real reasoning, not annotation matching.** `derive_activation_mechanism` (`chemistry_logic.py:354`) parses UniProt catalytic-activity *equations* to distinguish NTP→NMP+PPi (adenylation, Pα) from NTP→NDP+Pi (phosphorylation, Pγ), retains conflicts without voting, and attaches provenance. `classify_reaction_chemistry` + the generic all-7-class EC→bond map (`static/ec_bond_map.py`) give a reaction-agnostic bond/direction model. This is more than a BLAST-plus-LLM wrapper.

3. **The ranking spine is honest about LLM limits.** `_deterministic_mechanistic_ranking` (`output/report_generator.py:516`) is a strict lexicographic order over grounded facts (hard gate → family decision → substrate fit → mechanism-evidence tier → curation → structure → papers), with the LLM ranking explicitly non-authoritative best-effort on top (`:524-527`).

The most consequential weaknesses are: (a) the central ranking hypothesis — native-substrate similarity predicts non-native activity — is the very thing the group's own downstream work found non-predictive; (b) several controller "gates" that are documented/perceived as enforcement are advisory no-ops, and several swallow failures as "done"/"searched", permanently; (c) subtle firewall erosion in controller code and a persistent cross-run cache of named enzymes; (d) no reproducibility (no seed, provider-default temperature, model-switching failover) and no ablation that would show agentic reasoning *beats* a conventional pipeline; (e) the suite is currently red.

**Verdict:** a strong engineering artifact and a credible discovery *assistant*. As a *scientific research system* it is not yet falsifiable-by-construction: it cannot presently demonstrate that its agentic machinery improves discovery over a simple baseline, and it optimizes a proximity signal its own experiments contradict.

## B. Prioritized findings

### F1 — [High · Scientific validity] Ranking's dominant chemistry axis is native-substrate similarity, which the group's own data shows does not predict non-native activity
- **Location:** `output/report_generator.py:537` (P1), `prompts/sections.py:50-53` (P4), `chemistry_logic.py:709` `whole_package_pair_fit`, `:737` `compare_substrate_properties`.
- **Evidence:** After the hard gate and family decision, the first discriminating key is `fit_key` = functional-group/steric similarity of the **target** to the enzyme's **native** substrate (`report_generator.py:570-589`). P4 states the thesis outright: "An enzyme whose native substrate is structurally close to the target is often a better starting point."
- **Impact:** For non-native catalysis the whole challenge is that the substrate differs; proximity to the native substrate is exactly where sequence/annotation similarity is overinterpreted as functional similarity. The team's downstream structural/wet-lab results repeatedly found this signal non-predictive of the real endpoint (native-substrate "fit" anti-correlated with the right axis; proximity-weighted-angle improvers at chance; the metric ranks ammonia-native enzymes top for a diamine target). The discovery ranker is thus optimizing a quantity later measured to be uninformative — a systematic false-positive/false-negative driver at the top of the shortlist.
- **Recommendation:** Demote native-substrate similarity to a tiebreaker; rank primarily on mechanism compatibility (activated-intermediate match, cofactor availability, active-site electrophile class) and evidence tier. Report substrate-fit as a diagnostic, not a rank key. Make the P1/P4 weighting a logged, ablatable knob.
- **Validation:** Re-score a past campaign with substrate-fit removed from the rank key; compare recall@k of known actives. If recall does not drop, the axis was not earning its position.

### F2 — [High · Reproducibility] No determinism and model-switching failover make runs irreproducible; nothing tests it
- **Location:** `config.py:153` (`LLM_TEMPERATURE = None`), `llm_client.py:633` (temperature passed only if set), cascade in `llm_client.py:155-215` + `config.py` Gemini/Groq chains; no seeding anywhere in live source (verified by grep).
- **Evidence:** Provider-default sampling, no RNG seed, and a Gemini-cascade/Groq failover that advances to a *different reasoning model* mid-run on quota exhaustion. Seeds exist only for UMAP/PCA plots.
- **Impact:** Two identical invocations can yield different candidate sets and different recall; a mid-run failover silently changes the scientist. Recall/coverage numbers in any report are not reproducible, and cross-run comparisons (and the benchmark itself) are confounded by which model answered which turn.
- **Recommendation:** Set temperature 0 for science-bearing calls; pin the model in the run manifest and flag/fail the run if a fallback served any science call (provenance for model transitions already exists at `llm_client.py:162` — escalate it from record to gate). Add a record/replay LLM fixture with a golden-transcript regression test.
- **Validation:** Run the same config twice with temp 0 and a pinned model; assert identical candidate accession sets.

### F3 — [High · Scientific validity / Reproducibility] Persistent `data/mechanism_coordinate_cache.json` transfers one enzyme's reaction coordinate to another and carries named enzymes across runs
- **Location:** `tools/mechanism_extraction.py:508-531` (coordinate transfer, `coordinate_transferred=True`), `models/candidate_registry.py:745-752` (atlas hits stamped with seed's family), `tools/mechanism_cache.py` (get/put keyed by IPR id only); file verified present (22 KB, git-untracked, mode 600) containing `nylC`, `rutB`, `novL`.
- **Evidence:** Cache key is the broad InterPro family id with no reaction/substrate/direction/identity floor. When a hit's own extraction is ungrounded, `best["steps"]` is overwritten with another family member's coordinate and returned looking like a normal extraction. `register_atlas_homologs` sets `interpro_ids=[seed_family]`, `family_assignment_basis="structural_homology_to_seed"` with no domain check on the hit.
- **Impact:** (1) Scientific: an unannotated metagenomic structural hit inherits a catalytic family label and a *different* enzyme's mechanism coordinate as if grounded — a correctness bug that can promote and mis-rank. (2) Reproducibility/leakage: a process-wide, in-tree cache of named enzymes bleeds state across runs; `tools/mechanism_families.py:34-36` argues such caches must live *outside* the repo precisely so answer-adjacent names don't leak — this one violates that.
- **Recommendation:** Add target contract + sequence-identity floor to the cache key; mark transferred coordinates `unvalidated` and exclude from grounded evidence; require an InterPro lookup on the hit sequence before assigning a family; move the cache out of the package tree.
- **Validation:** Unit test: two reactions sharing an IPR must not share a cached coordinate; an atlas hit with no domain hit must not receive a family id.

### F4 — [High · Reliability] Transient API failures are silently recorded as "empty results" or "searched", sometimes permanently
- **Location:** `tools/database.py:628-643` (`_interpro_fetch` bare `except: continue`→`None`); `tools/structural_homolog_search.py:99-130` + `models/expansion.py:236-243` (seed marked searched on `partial`); `tools/esm_atlas_expansion.py:97-127`; `chemistry_logic.py:55-61` (ChEBI failure cached as `None`, verified `:60`); `tools/esm_expansion.py:121-128` (family FASTA bypasses `request_with_retry`, returns `{}` on error).
- **Evidence:** A 503 on an InterPro query triggers query *relaxation* and returns `status:"success"` for a broader family; a genuine 204 empty returns `"error"`. A Foldseek/AFDB timeout returns `partial`, and `searched_seeds` counts `partial` as done → the seed is never retried. One ChEBI/PubChem timeout makes a compound unresolvable process-wide, which (via `reasoning.py:955-970`) suppresses the Rhea/literature substrate-fallback cascade and can read as 0.0 substrate fit rather than "unknown".
- **Impact:** Network weather silently becomes scientific signal: false "broader family found", false "no homologs", false "poor fit". False negatives are invisible and permanent within a run; coverage/expansion statistics over-count completed-but-failed attempts.
- **Recommendation:** Tri-state every fetch (`ok_data` / `ok_empty` / `unavailable`); count only `success`+true-empty as searched; cache only confirmed negatives (200-with-no-result or 404); never relax a query on `unavailable`; route `esm_expansion` family fetch through `request_with_retry`.
- **Validation:** Inject 503/timeout via a stub transport; assert the seed/compound is retryable and the tool reports `unavailable`, not success/empty.

### F5 — [High · Agent reasoning] Documented coverage enforcement is a no-op; it cannot gate evaluation
- **Location:** `gates/discovery_coverage.py:94-100,140`, `gates/ec_triage.py:492` (guards on `not discovery_coverage_incomplete`), `agent.py:798` (resets flag to `False` every `_sync_gate_state`, verified).
- **Evidence:** Every path (including the intercepting one) sets `discovery_coverage_incomplete=False`, and `_sync_gate_state` resets it each turn, so the flag ECTriage reads is never True. The 4-screened/4-family "contract" (`models/target_profile.py:36-38`) emits one advisory redirect and then never constrains anything.
- **Impact:** Reports/claims that treat coverage as an enforced precondition are inaccurate; a run can finalize without meeting its own declared coverage. The "contract" is cosmetic.
- **Recommendation:** Either delete the flag and the enforcement language, or make coverage a real precondition with an explicit escape budget.
- **Validation:** Test a run that screens <4 candidates in 1 family and assert evaluation is blocked (or that no doc claims it is).

### F6 — [High · Scientific validity / firewall] Answer-adjacent vocabulary in controller code and an injected prompt; the firewall's own grep misses it
- **Location:** `gates/ec_triage.py:449-452` (blacklist contains `ANL`, `NIS`); `gates/family_survey.py:317-318` (injected LLM prompt enumerates classes to STOP: "peptide, amino acid, nucleotide, sugar, or cofactor"); `gates/mechanism_family_coverage.py:92` (comment names forbidden example families); CLAUDE.md grep uses `/runs/` which fails to exclude relative `runs/` paths (150+ false hits mask real ones).
- **Evidence:** `ANL`/`NIS` are the answer-family acronyms (acyl-adenylate-forming superfamily; NRPS-independent siderophore synthetase); their presence in a stopword blacklist shows the controller anticipates the answer vocabulary, and the mandated grep (`NIS synthet`) doesn't catch bare `NIS`. The `family_survey` text reaches the model and is exactly the "enumerate the wrong classes" pattern CLAUDE.md rule 3 forbids.
- **Impact:** Erodes the central claim that the agent is answer-blind. For the amide benchmark the STOP enumeration conveniently excludes the wrong families; a reviewer running the documented grep gets a false all-clear.
- **Recommendation:** Derive stopwords from the target/generic lexicon, not a hand list; replace the class enumeration with grounded numeric criteria ("stop folds whose measured native-substrate fit is below X"); fix the firewall grep to `--exclude-dir` and add `ANL|NIS|adenylation|glutamine synthetase`; add a test that scans *injected prompts*, not just `.py` source.
- **Validation:** The corrected grep returns empty; a prompt-content test fails on the current `family_survey` string.

### F7 — [High · Reliability] Suite is red on master; reproducibility/science paths are largely untested
- **Location:** `tests/test_packaging.py:77` fails (`enzyme_design_agent.tools.rfd4_campaign` missing from wheel packages) — reproduced directly (`1 failed, 6 passed`). Full suite: 1 failed / 898 passed / 8 skipped.
- **Evidence:** The failure is a genuine packaging omission tied to the uncommitted sibling-package work in git status. Separately, the LLM and network layers are mostly mocked; `test_decision_evals.py` `self_check` asserts "no model was evaluated"; there is no end-to-end test that the agent infers the correct mechanism/rejects a wrong bond type, no determinism test, no mid-run-outage test, and no DB-version-drift test.
- **Impact:** No green CI gate; the science-determining (LLM-driven) behavior is unverified; deterministic rule logic is well tested (`test_claim_validation.py`, `test_substrate_accommodation.py`, `test_mechanism_extraction.py`) but that is the part least likely to be wrong.
- **Recommendation:** Fix `pyproject` packages (or `find:`); gate merges on pytest; add golden-transcript replay tests for ranking and for one full discovery turn; add stub-transport outage tests (ties to F4).
- **Validation:** `pytest` green in CI; golden tests fail on ranking drift.

### F8 — [Medium · Scientific evaluation] No baseline/ablation — the benchmark measures the agent's recall, not whether agentic reasoning helps
- **Location:** `eval/benchmarks.py` (recall oracle, answers never fed to agent — good), `eval/counterfactuals.py` (constraint-sensitivity, not a baseline), `eval/metrics.py`.
- **Evidence:** Scoring computes recall/coverage of one system against ground truth. `eval/counterfactuals.py` tests whether the agent responds to constraint changes, not whether the full pipeline beats a plain UniProt/keyword/BLAST search or an LLM-without-gates. Primary targets are tiny (amide: 2 accessions → floor p≈0.02).
- **Impact:** The headline novelty (agentic reasoning) is unfalsifiable as stated: there is no counterfactual showing the gates/mechanism-reasoning/expansion add recall over a conventional pipeline. Underpowered n compounds this.
- **Recommendation:** Add three baselines run through the same scorer — (i) single UniProt query from the raw query, (ii) LLM-plans-then-one-shot-search (no gates/expansion), (iii) full agent — and report recall@k with CIs across ≥10 benchmarks. Add ablations toggling each gate family.
- **Validation:** A table where full-agent recall exceeds baselines with non-overlapping CIs would substantiate the claim; if not, it bounds the contribution.

### F9 — [Medium · Reliability/Agent reasoning] A single failed/empty LLM response permanently disables a reasoning gate
- **Location:** `gates/mechanism_family_coverage.py:303-309` (sets `mechanism_families_done=True` when `derive_mechanism_families` returns `[]` for any reason); `tools/mechanism_families.py:374-378` (returns `[]` on `llm_client is None` or all-dropped); `gates/literature_harvest.py:190-196` (harvest exception swallowed, still writes "batch processed").
- **Evidence:** Malformed JSON or all-families-dropped-by-filter is indistinguishable from "legitimately none", and turns off mechanism-led discovery for the whole run with no retry and no agent-visible warning; FamilySurvey then proceeds on discovered folds only.
- **Impact:** One transient LLM hiccup silently collapses the breadth-first mechanism enumeration that is the system's main differentiator — precisely the premature-convergence failure the prompts are designed to prevent.
- **Recommendation:** Distinguish "derived nothing" from "LLM failed"; retry with a cap; write a degraded-run marker surfaced in the report.
- **Validation:** Stub a malformed LLM response; assert the gate retries and the run is flagged degraded, not silently narrowed.

### F10 — [Medium · Reliability] Gate control flow is index-addressed, mutates state in predicates, and can re-fire without durable progress
- **Location:** `agent.py:1070,1102,1104` (`self._gate_pipeline.gates[2]`/`[3]` by magic index); `gates/family_survey.py:63-84,147,197` (`should_fire` resets attempts/`family_survey_done`; registry count captured before promotion, so any promotion re-arms the 6-attempt cap); `agent.py:439-463` (every intercept refunds the iteration).
- **Evidence:** The same gate objects run from three loops in two different orders; nothing documents that `gates[2]` must be ECTriage. FamilySurvey re-arms itself via its own promotions; failed folds aren't recorded so they retry every firing. Budget-deferred homolog/systematic searches return `intercept=True` without recording progress, and refunds mean gate spins consume no iteration credit — only the global budget ends them.
- **Impact:** Fragile to reordering; near-budget runs can burn model turns on empty gate messages; FamilySurvey can exceed its documented cap and re-issue up to 16 survey calls per firing.
- **Recommendation:** Name gates with declared `requires`/`provides` flags and assert ordering at construction; capture registry count after promotion; track failed folds with a retry limit; don't intercept when all work was deferred/errored.
- **Validation:** Reorder the pipeline list and assert a construction-time error; simulate all-deferred expansion and assert no intercept.

### F11 — [Medium · Scientific validity] Foldseek `tm_score` is read from a field named `eval`, and structural homology (TM 0.5) is treated as a reaction signal
- **Location:** `tools/structural_homolog_search.py:59` (`tm_score = float(alignment.get("eval"))`, verified; bounded-to-[0,1] guard at `:60`), `:21` (AF-header-only; PDB hits dropped despite "AlphaFold DB and PDB" claim); `gates/homolog_expansion.py:62` (`min_tm_score=0.5`, `max_hits=10`).
- **Evidence (partly inference — live field not confirmed):** If the server returns an E-value in `eval`, the `>=0.5` filter inverts (small-E good hits score ~0 and are dropped; the [0,1] guard nulls E>1). The only fixture (`tests/test_bootstrap.py:307`) is developer-authored, so it does not independently confirm the field. TM 0.5 is weakly related to catalytic function.
- **Impact:** Potential systematic loss of the best structural homologs, and over-interpretation of fold similarity as mechanistic similarity in expansion.
- **Recommendation:** Add a recorded-response contract test for the Foldseek endpoint; request `alntmscore` explicitly; parse PDB headers or drop the claim; label structural expansion as candidate-generation only (the gate text already does this — keep it).
- **Validation:** Contract test against a saved Foldseek response; assert small-E/high-TM hits survive the filter.

### F12 — [Medium · Scientific validity] UniProt/Rhea query handling can silently broaden or mix sides
- **Location:** `tools/database.py:105-130` (`_relax_uniprot_query` drops trailing terms, incl. organism; relaxation only in free-text summary, `status` stays success; no `x-total-results`/pagination); `tools/reasoning.py:593-635` (`_fallback_substrate_lookup` returns **products** as well as substrates — the primary path is deliberately reactant-only, `family_reactions.py:317`); two divergent UniProt parsers (`database.py` vs `_parse_uniprot_json`) read EC from different fields.
- **Evidence:** Relaxed queries lose exactly the qualifiers (organism) that scope them, unflagged; the Rhea fallback has no side filter, so product SMILES can enter the substrate-accommodation score; TrEMBL entries with EC only in `submissionNames` lose their direction check in `family_reactions._member_ec`.
- **Impact:** Overbroad/mixed-taxon hits presented as clean successes; product chemistry contaminating substrate fit; inconsistent EC extraction across code paths.
- **Recommendation:** Return `used_query`/`relaxed_from` and `total_hits` as structured fields with per-hit flags; filter the Rhea fallback to the reactant side; unify on one UniProt parser.
- **Validation:** Test that a relaxed query is flagged and that `_fallback_substrate_lookup` never returns a product CHEBI.

### F13 — [Low · Scientific validity] Benchmark-adjacent examples in tool descriptions; OpenAlex defaults to citation sort
- **Location:** `tools/database.py:138` (`'ec:3.5.1.* AND amidase'` example), `:505-527` (`6.3.1.2` = glutamine synthetase example), `tools/literature.py:722-740` (`sort_by_citations=True` default), `config.py:325` (semantic rerank off by default), embedder loaded `trust_remote_code=True` with no pinned revision (`literature.py:58,76-80`).
- **Impact:** Example EC/enzymes in tool descriptions can prime the model toward the campaign's families (soft leakage); citation-sorted literature buries new low-cited enzyme papers (recency bias against exactly the novel enzymes discovery wants); unpinned remote-code embedder is a reproducibility + supply-chain risk.
- **Recommendation:** Genericize tool-description examples; default literature to relevance sort; pin the embedder revision.
- **Validation:** Firewall/example-scan test over tool descriptions; config test asserting relevance default.

## C. End-to-end reasoning audit — "ligate adipic acid + HMD → nylon-6,6 amide diad"

| Stage | What happens | Mode |
|---|---|---|
| 1. Interpret chemistry | User substrates → SMILES via ChEBI/PubChem (`chemistry_logic.py`); bond/direction from `extract_target_bond_type` keyword map (`:519`); the prompt forces "decompose before searching" (`prompts/sections.py` P1). Bond = amide, direction = formation. | Deterministic parse + **LLM** strategy framing. Note the **amide↔C-N hardcode** (`:667-670`) is the only bond with a vocabulary-unification special case — latent benchmark bias. |
| 2. Mechanistic hypotheses | Prompt Step B asks for 2–4 mechanisms with distinct activated intermediates/folds (`prompts/sections.py:93-97`); `derive_mechanism_families` (LLM) proposes families, then `family_passes_constraints` filters by direction/topology. | **LLM-driven**, code-filtered. Genuinely generative — this is the strongest agentic step. Fragile per **F9** (one bad response disables it). |
| 3. Family selection | FamilySurvey walks InterPro folds, auto-promotes relevant members; the injected STOP-list (`family_survey.py:317`) tells the model which native-substrate classes to drop. | Heuristic/tool-driven; LLM calls `set_family_focus`. **Leakage per F6.** |
| 4. Retrieve/interpret evidence | UniProt/Rhea/literature via tools; `evaluate_candidate` fetches live records, validates claims, parses catalytic-activity equations, derives activation mode + cofactors. | Deterministic + grounded; **the firewall's strong point.** Degraded silently under outages (**F4**). |
| 5. Filter/rank | `screen_candidates` rejects on direction/identity; deterministic lexicographic rank with substrate-fit as top discriminator; LLM focus-rank overlay. | Deterministic spine + LLM overlay. **F1** (wrong primary axis) and the atlas family-stamp/coordinate-transfer (**F3**) bite here. |
| 6. Uncertainty/contradiction | `claim_validation` emits contradicted/insufficient; conflicting activation signatures retained not voted (`chemistry_logic.py:399`); recovery bounded to durable evidence (`models/recovery.py`). | Deterministic, and well done. But no test of resolving two conflicting source claims; transient failures masquerade as negatives (**F4**). |
| 7. Recommendations | Shortlist + structural-modeling handoff JSON. | Deterministic assembly. |

**Overall:** genuinely adaptive and LLM-driven at stages 1–2 (chemistry decomposition, mechanism enumeration) — this is not just automated database search. Stages 3–7 are mostly deterministic heuristics; the agent's strategic influence reaches them through `mechanism_families.json`, the target profile, and `set_family_focus`. The reasoning that is observable and measurable is the mechanistic chemistry (strong); the reasoning that most needs validation (family inclusion/exclusion, ranking) is where leakage, no-op gates, and the contradicted proximity axis concentrate.

## E. Research-level assessment

1. **Strongest scientific contribution.** The evidence-grounded, firewall-respecting pipeline that turns a reaction into mechanistic hypotheses and then *verifies every candidate against live database records* — in particular the catalytic-activity-equation parsing that infers adenylation vs. phosphorylation with retained conflicts and provenance (`chemistry_logic.py:354`). That is reasoning conventional sequence search cannot do, and it is answer-blind by construction at the candidate-entry boundary.

2. **Three most serious weaknesses.** (i) The ranking optimizes native-substrate similarity, which the group's own downstream experiments found non-predictive of non-native activity (F1). (ii) Irreproducibility: no seed, provider-default sampling, model-switching failover, no determinism test (F2) — results cannot be reliably reproduced or compared. (iii) Silent degradation: transient failures become permanent scientific negatives, a reasoning gate self-disables on one bad response, a documented coverage gate is a no-op, and a cross-run cache transfers one enzyme's mechanism to another (F3, F4, F5, F9).

3. **Genuinely novel reasoning.** The mechanism-first decomposition (enumerate distinct activated intermediates/folds *before* searching) and the equation-level activation-mode inference are the novel parts. The rest is a well-engineered but conventional retrieve-filter-rank pipeline with an LLM overlay.

4. **Experiments that would demonstrate agentic reasoning helps.** (a) Baseline ladder through the same scorer: raw-query UniProt search vs. LLM-plan-then-one-shot vs. full agent, recall@k with CIs over ≥10 benchmarks. (b) Gate ablations (mechanism-enumeration on/off, structural/ESM expansion on/off, deterministic-rank vs. LLM-rank vs. random). (c) A perturbation test: paraphrase the query and swap models — stable recall would evidence robust reasoning rather than prompt/model luck. (d) Prospective wet-lab test of the top-k the agent ranks *by mechanism* vs. *by substrate fit* (directly adjudicates F1).

5. **What most improves credibility as a publishable system.** The baseline/ablation harness (F8) — without a counterfactual the central claim is unfalsifiable. Then determinism (F2), honest failure semantics (F4), and closing the firewall gaps + the no-op coverage claim (F5, F6), so that stated guarantees match behavior. These turn an impressive assistant into a system whose scientific contribution can be measured and defended.
