# Reaction barrier implementation review — 2026-11-11

The electrostatic-embedding core implements a meaningful additive DFT/MM model:
MM point charges enter SCF, classical QM Coulomb terms are removed, and QM, MM
and link-parent derivatives are combined. This matches the decomposition in the
[PySCF QM/MM documentation](https://pyscf.org/user/qmmm.html). It remains a finite,
fixed-membership model, with a separate remaining-MM reaction-field Hamiltonian.
Passing force derivatives does not demonstrate a quantitatively converged
enzyme barrier.

The baseline suite passed 41 tests in the managed quantum environment, with the
RDKit test module skipped. The existing Nov-11 enzyme GPU derivative records
are historical evidence for their recorded numerical profiles. They were read,
not regenerated or modified during this review. No new full-enzyme GPU job or
barrier production campaign was launched.

## Confirmed defects and corrections

| Finding | Consequence before correction | Correction |
|---|---|---|
| Cluster initialization inferred fragments from interatomic distances | A metal-connected geometric graph could move the electrophile or an unintended fragment | Record authoritative cluster bonds; move declared substrate/leaving fragments; reject frozen-atom motion |
| Legacy scans ignored optimizer convergence | A finite energy after exhausting optimization steps could become a reported scan gap | Reject unconverged or nonfinite scan images |
| Path reconstruction accepted different partitions/topologies | Energies from different Hamiltonians could be compared | Check topology bytes, full region identity, coordinate shapes and cells across snapshots |
| Recorded cell lookup ignored `box_lengths_angles` | A topology or rounded PDB cell could override the snapshot's actual cell | Prefer the recorded coordinate-cell field and reject changed cells |
| Minimum-image recovery searched only one cell from the original displacement | Multi-cell image shifts could survive reconstruction | Reduce the displacement into the reference lattice before the neighboring-cell search |
| Optional cap-charge redistribution could recharge a link parent | Boundary policy could be violated despite conserving total charge | Exclude all link parents from redistribution; reject an empty recipient pool |
| Draft embedding runner selected individual atoms, labeled finite shells “full-cell neutral,” and forced CPU MM with grid response off | Split charge groups and misleading method provenance; settings differed from the tested profile | Select whole residues, report actual shell charge, default to full grid response and the backend's requested platform |
| QM snapshots assumed singlet spin and metal charge +2 | New chemistry could silently receive an incorrect electronic state | Respect declared multiplicity and metal charges; use UKS for open-shell DFT and spin-summed MM-force density |
| Atom-name lookup silently chose the first match; AUTO ignored residue disambiguation | A different copy of a ligand could supply the reaction atom | Reject ambiguous names and honor the requested residue for AUTO |
| Legacy cluster construction did not check declared ligand charges or reimage periodic molecules | Wrong protonation/charge or a remote periodic image could enter a cluster | Validate declared molecular/metal charges, load authoritative coordinates and reimage whole molecules |
| Shared paths and endpoint summaries assumed phosphate distances and acyl-oxygen chemistry | Other bond exchanges could be driven or classified incorrectly | Store reaction-specific targets and use a generic bond-exchange classifier; preserve specialized phosphate checks as an option |
| Scan energies and optional external Hessians could use different UMA profiles | The thermochemistry correction could belong to a different numerical potential | Centralize UMA settings and calculate partial Hessians with the same attached calculator |
| qRRHO accepted an uncertified scan maximum without stationary/index checks | Nonstationary structures could receive an apparent free-energy correction | Require stationary seeds, pinned boundary and expected Hessian indices; preserve the exploratory reporting restriction |
| NaN uncertainties, ESS and sparse inclusion probabilities were not consistently rejected | Invalid data could pass a reporting gate or propagate into reweighting | Require finite admissible values, valid starting-configuration hashes and positive finite temperatures |
| Water trimming was described as guaranteed to cancel and reported the untrimmed atom count | Resource approximations could be mistaken for an unchanged model | Retain mobile residues, report actual evaluated atom count and require trimming sensitivity checks |

## Organization

The implementation now belongs to `structural_modeling_agent.barrier`. Its
lightweight API owns input preparation and result review; the structural
controller offers corresponding tools. The former top-level package contains
thin compatibility entry points, with shared module/class identity. Existing
run directories, frozen producer copies and numerical outputs are preserved.

The preparation helpers do not select a potential, infer a production-ready
mechanism, or launch compute. Heavy imports are deferred to the selected
operator. UMA setup is shared by cluster, full-system and UMA/xTB operators;
the core scan and thermochemistry no longer import a machine-specific common
helper tree.

## Verification and remaining scientific limits

Regression coverage includes real Amber-topology preparation for a non-phosphate
fixture, explicit Zn charge and coordination-shell selection, open-shell CPU
DFT/MM force differences, topology-preserving path initialization, partition/cell
rejection, cap-charge conservation, optimizer failure, partial-Hessian index,
the harmonic limit of qRRHO, nonfinite evidence rejection, and compatibility
imports/CLI entry points. Structural-agent tools and package declarations are
also checked. Final targeted validation passed 80 tests in the managed quantum
environment and 34 chemistry/controller tests in the project environment. The
quantum environment skipped its missing RDKit module; those three chemistry
tests passed in the project environment. The wheel built successfully and its
canonical/compatibility imports were checked outside the source checkout.

These checks establish software properties. The new open-shell test uses a
small water-cation fixture; it does not validate transition-metal enzyme spin
surfaces or GPU UKS gradients. The Zn test checks partition construction, not
metal energetics. Heavy elements using def2 bases require an explicit reviewed
ECP. Existing Mg C4 requirements remain in force.

An enzyme-specific application still needs a chemically justified molecular
graph, exact sequence/assembly, proton inventory, electronic/spin state, metal
parameters and bound-state reference. Investigate basis, grid, QM-region,
embedding-radius and boundary sensitivity; establish saddle connectivity or
adequate finite-temperature sampling. The present high-level path specification
describes one bond exchange. Multi-step, proton-coupled or redox mechanisms need
separate explicit setups and additional coordinates where appropriate. No
validated enzyme activation free energy is produced by this refactor alone.
